What the tag row does when it stops fitting

Four ways to handle a filter row that outgrows one line, drawn 2026-08-20 at Thomas's request. The open question is his to close in Figma — this exists so there is something to argue with rather than a blank frame.

These are Claude's sketches, not design. Grey pills on purpose — no DS tokens, no type ramp, no Figma. Nothing here is a decision, and the real chips are the DS Chip component that already ships in src/components/ui/chip.tsx.
Settled already, and it shapes all four: tags multi-select and combine with AND, and Favorites joins them in the same row instead of staying a radio. So any number of chips can be lit at once — which is exactly why a chip that is ON must never be the one that scrolls out of sight.

A · Swipe the row sideways

one line, scrolls horizontally
Search recipes
AlldessertFavorites quickveggie

Active chips pulled to the front so the filter is always visible.

The cheapest build and the standard iOS pattern — App Store, Music and Photos all do it. Costs no vertical space at all, which matters in the add-meal sheet.

Good: nothing new to build, no height, scales to any number.
Bad: you cannot see what tags exist without swiping, so the family forgets its own vocabulary. And re-sorting active chips to the front means the row reshuffles under your thumb — the chip you just tapped jumps somewhere else.

B · Let it wrap to two lines

No interaction needed — the whole vocabulary is just there.

Best answer for a small set, and a family cookbook probably is one. Six to eight tags fit two lines with room to spare.

Good: zero taps to see everything; no reshuffling; an active chip can never hide.
Bad: eats vertical space above the list, and the block changes height as tags are added — the recipes jump down the screen. At fifteen tags it is four lines and half the screen is chrome.

One component, one cap per canvas: two lines on the recipes list, one line in the sheet. Below the cap it is option B and costs one tap. Above it, the last slot becomes an overflow chip opening option C's sheet. The family that makes five tags never sees the sheet exist; the family that makes twenty is not punished.

The honest cost: it is two surfaces, so it is the expensive answer — the same trap as the ingredient-alias sketch. If a real cookbook turns out to hold six tags, B alone is the right build and this is over-engineering.

This is the condition attached to the AND decision, not a nice-to-have. AND teaches itself while the list shrinks — thirty recipes become three and the meaning is obvious without a word. The moment it hits zero, that teaching stops and it reads as an empty cookbook or a broken screen.

So the empty state names both tags and offers a one-tap way out. It is also the most likely state in the add-meal sheet, where the library is small and the questions are specific — “quick and veggie, for Tuesday”.

Still open — and B vs D is not the first one

How many tags does a real family make?Nobody knows, and it decides B against D outright. Six means B; twenty means D. Worth a guess out loud before drawing either.
What order do the chips sit in?Alphabetical is predictable and builds muscle memory. Most-used-first is smarter and reshuffles the row between visits, which is the same disorientation A was marked down for.
Where does a NEW tag get made?Not drawn here at all. On the recipe, presumably — but the picker that adds and chooses tags is its own frame and its own conversation.
Does the sheet row scroll away?The add-meal chip row rides in the list header today, so it scrolls off with the content. With a filter switched on, that hides the reason the list looks short.
Also considered and not drawn: tags only in the search field — type “dessert”, get the tagged recipes, no chip row beyond the two that ship today. It is free, and search will match tag names anyway. It is not drawn because it is not the feature: Thomas asked to tap a tag the way you tap a favourite, and typing is not tapping. Worth knowing it exists as the fallback if the row never earns its space.

Claude's leaning, recorded for whoever picks this up: D, built so that a small cookbook is indistinguishable from B — and if the answer to “how many tags” turns out to be six, build B and stop.
